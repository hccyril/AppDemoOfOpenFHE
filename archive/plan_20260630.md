BCHP 演示修复方案：从 14ms 还原到论文 §6.3 的秒级运行时间
问题根因总结
经核查论文 §6.1/6.2/6.3 与现有代码，14ms 远低于预期（5秒以上）的根因有 4 个复合问题：

#	问题	现状	论文要求
1	参数低 3 个数量级	n=2048, q=40961(≈2¹⁶)	N=2¹⁴=16384, q≈2⁶⁰
2	工作负载极小	m=3 行, k=2 → 仅 12 次环乘	256/512/1024 → N²≈2.7×10⁸ 次
3	违背"归约到 BLAS"思想	用 OpenFHE NTT 环乘 (operator*) 做矩阵乘	应归约为 OpenBLAS 浮点 dgemm
4	没有 CC-MM 演示	Demo C 只是单次 HomMul+Relin	§6.3 报告 256×256≈18s, 1024×1024≈278s
关键技术约束（已核实 OpenFHE 源码）：

NativeInteger 在 NATIVEINT==64 下 MAX_MODULUS_SIZE=60，原生支持 q≈2⁶⁰ ✓
usint = uint32_t（最大 ~4.3×10⁹），无法装下 2⁶⁰ → MLWEParams.q 字段需扩展
FirstPrime(nBits, 2n) 可直接生成满足 q≡1 mod 2n 的 ~60 bit NTT-friendly 素数
现有 MLWEContext 构造函数硬编码 q % (2*n) != 1 校验，需配合 q 字段扩展
修复方案（按用户选择：完整 BLAS 归约 + 多规模 256/512/1024）
第 1 步：扩展 mlwe.h / mlwe.cpp — 支持大模数 q
MLWEParams 新增 uint64_t q64 字段（保留 usint q 向后兼容旧 demo），并提供大模数构造路径。
MLWEContext 内部用 FirstPrime(60, 2n) 自动生成 ~2⁶⁰ NTT-friendly 素数（当 q64=0 时）；校验逻辑改为支持 64-bit q。
新增工具函数 RingMulByConstant(环元素×标量，已有可复用)、GetModulusAsU64。
不改 KeyGen/Encrypt/Decrypt/Add/HomMul/Relin/Automorphism 的数学语义，仅让它们能接受大 q（它们本就通过环参数工作，天然支持）。
第 2 步：在 bchp.h / bchp.cpp 实现"完整 BLAS 归约"内核
新增论文核心算法 —— 模 q 整数矩阵乘归约到 OpenBLAS：


text
ModularMatMul_dgemm(A, B, q):  // A∈Z_q^{r×s}, B∈Z_q^{s×t}, 输出 A·B mod q
  // 用 digit-decomposition(基 base, 如 2^15) 把 [0,q) 系数拆成高位/低位段
  // 每段系数 < base，base² < 2^53 (double 精确整数上限)，保证 dgemm 累加不丢精度
  // 对 A 拆成 A=A_lo + base·A_hi, B 同理
  //   C = A_lo·B_lo + base·(A_lo·B_hi + A_hi·B_lo) + base²·A_hi·B_hi
  // 每项调一次 cblas_dgemm(列优先 double)
  // 最后对 C 逐元素 mod q 归约（double→int64→Mod）
这是论文 §1.1/§5 "把同态矩阵乘归约到明文 BLAS" 的真正实现，替代当前用 NTT 环乘的错误做法。

基于此重写：

Algorithm6_CPMM：(A·U, B·U) 的明文核改用 ModularMatMul_dgemm（系数矩阵按列打包进 dgemm），保留 S*·A+B≈Δ·M 解密关系。
新增 Algorithm4_CCMM（§5.3 / Algorithm 4）：两个矩阵密文相乘，归约为 4 次 ModularMatMul_dgemm（A·A', A·B', B·A', B·B'），对应论文 §6.3。
明文矩阵在 double 数组 ↔ 环元素系数 之间双向转换的辅助函数 FlattenCoeffs / PackCoeffs。
